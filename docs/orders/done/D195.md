# D195 — من م٧ الخطوة ٢: مولّد قاعدة الإصدار يجري ترقيات الإقلاع نفسها

> الوسم: ⚙️ · الحجم: ص (ملفّ اختبار) · يعتمد على: قول المالك «ارفع الإصدار إلى 1.9.0» (٢٦ ت١) · بعده: إيداع الخطوة ٢ · القرار: A02 (D49)، A17 (D148)، ر177 §٣
> كتبه المنفّذ في الخطوة ٢ من محطّة الإصدار (٢٦ ت١).

## الهدف
`tests/makeReleaseDb.test.ts` يبني قاعدة الإصدار بطريق الإقلاع الحقيقيّ — `schema.sql` و`search.sql` ثم `runMigrations` ثم `prepareSearch` — كما يقول رأسه
(«بخدمات هذا الإصدار نفسه وترحيلات إقلاعه»)، فتُصنع `tests/fixtures/release-1.9.0.db`.

## الدليل (مُجرَّب)
`RELEASE_OUT=tests/fixtures/release-1.9.0.db npx vitest run tests/makeReleaseDb.test.ts` ← ✗ «table orders has no column named received» في `saveOrder` ·
والمولّد ينادي بيده سبع دوالّ `prepare*`/`ensure*` وليس منها `prepareOrders` ولا `prepareGenderMemory` ولا الترقية ١٠ — ومنذ A17 (D148، ٢٤ ت١) لا تناديها الخدمات عند الطلب
بل المشغّل وحده (`db/migrations.ts`)؛ فلم يُشغَّل المولّد منذ ١٫٨٫٠ (D42، ١٧ ت١) حتى سقط اليوم.

## المسموح
`tests/makeReleaseDb.test.ts` (التهيئة واستيراداتها وحدها) · `tests/migrationRunner.test.ts` (سطر المستوى قبل الترقية: ١٫٩٫٠ أوّل قاعدةٍ كتبها المشغّل — زِيد في التنفيذ) · `tests/fixtures/release-1.9.0.db` (جديد) · PLAN · الدفتر · هذا الأمر.

## الخطوات
١. مكان النداءات السبعة: `runMigrations(db)` ثم `prepareSearch(db)` — وما لم يعد مستعمَلًا من الاستيرادات يُزال؛ وما يكتبه المولّد بعدها كما هو.
٢. `RELEASE_OUT=tests/fixtures/release-1.9.0.db npx vitest run tests/makeReleaseDb.test.ts` ← القاعدة بلا `-wal` ولا `-shm` (كقاعدة ١٫٨٫٠)، و`releaseDb` بـ`SOLD` معها.

## الممنوع
تغيير ما يُكتب في القاعدة · مسّ `src/`.

## الفحص
`npx vitest run tests/makeReleaseDb.test.ts tests/releaseDb.test.ts tests/migrationRunner.test.ts` ثم مع الخطوة ٢: typecheck وvitest كاملًا.

## الختام
✅ في PLAN، وقيدٌ في الدفتر، ونقل الأمر إلى `docs/orders/done/` — مع إيداع الخطوة ٢.
