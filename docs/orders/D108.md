# D108 — إصلاح سباق عمال التعرّف (E03) وإغلاق مصادر PDF عند مغادرة الشاشة (E02)

> الوسم: ⚙️ · الحجم: ص · يعتمد على: D107 · بعده: D109 · البنود: E03 وE02
> كتبه D107 مفصّلاً: علّتان صريحتان في الكود القائم تؤذيان الذاكرة والتعرّف بلا مكتباتٍ جديدة.

## الهدف
١) حراسة `getWorker` و`getPageWorker` في `src/main/services/ocr.ts` بوعدٍ مشترك لمنع سباق تهيئة عاملين وتسرّب الذاكرة عند استدعاءين متزامنين (E03).
٢) إغلاق مصادر PDF عند مغادرة شاشة PDF في `screens/PdfScreen.tsx` باستدعاء `pdf:close` (E02).

## اقرأ فقط
`src/main/services/ocr.ts` (الأسطر 30–75) · `src/renderer/src/screens/PdfScreen.tsx` و`usePdfOpen.ts` · `src/main/ipc/pdf.ts` (القناة `pdf:close`) · `docs/sections/pdf.md` و`scan.md`.

## تحقّق قبل البدء
D107 ✅ في PLAN · `npm run typecheck` نظيف. وإلا: **توقّف.**

## المسموح
`src/main/services/ocr.ts` · `src/renderer/src/screens/PdfScreen.tsx` (أو خطّاف مغادرتها) · `tests/ocr.test.ts` (أو إضافة فحص السباق) · PLAN والدفتر.

## الخطوات
١. **E03 (سباق عمال التعرّف):** في `ocr.ts`، حفظ وعد التهيئة الجارية (`workerInitPromise` و`pageWorkerInitPromise`)؛ فإن طُلب العامل أثناء تهيئته انتظر الوعد نفسه، ولا يُنشأ عاملان قطّ، وإن فشل أُعيد تصفير الوعد ليُعاد المحاولة.
٢. **E02 (إغلاق مصادر PDF):** عند إلغاء تركيب `PdfScreen` أو مغادرتها، استدعاء `window.diwan.tools.pdf.close(openIds)` للمصادر المفتوحة، فلا تظلّ في ذاكرة النواة.
٣. **الاختبار:** اختبار وحدة لـ`getWorker` المتزامن يثبت استدعاء `createWorker` مرّةً واحدة فقط.

## الممنوع
تغيير سلوك `recognize` أو `recognizeLayout` · حزم أو مكتبات جديدة · تعديل خارج نطاق الملفّين.

## الفحص
`npm run typecheck` · `npx vitest run tests/ocr.test.ts tests/pdfEdit.test.ts` · سيناريو `node tools/drive.mjs tools/scenarios/pdfTools.mjs`.
