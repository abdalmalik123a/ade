# D105 — المحرّك في البرنامج كلّه: سيناريوهات Photoshop على البناء وعلى المحزوم، وقياس الفرق (A20)

> الوسم: ⚙️ · الحجم: ك · يعتمد على: D104 وتحقّق Claude منه · بعده: D106 (والجلسة نفسها: ك + ص = ٤) · البند: A20 (ر164)
> كتبه D102 وأعاد كتابته تحقّق Claude (١٩ ت١): PNG يبقى بـTS، فلا «تسطيح PNG في Rust» ولا crate صور؛ والمحزوم يُشغَّل لا يُعدّ ملفّاته وحدها.

## الهدف
يثبت أنّ استيراد Photoshop في البرنامج يمرّ بمحرّك Rust (لا بالبديل صامتًا) على بناء التطوير وعلى البرنامج المحزوم، بالنتيجة نفسها،
ويُقاس زمن `readPsd` بالمحرّكين على ملفٍّ كبير فيُعرف أفاد Rust أم لا.

## اقرأ فقط
`tools/scenarios/designPsd.mjs` و`designPsdStyles.mjs` و`workerPath.mjs` · `tools/drive.mjs` (`DIWAN_EXE` و`KEEP_RUN`) · `src/main/services/workerHost.ts` (`logError('native')`) ·
`tests/nativePsdCompare.test.ts` · `tools/experiments/measure.mjs` (طريقة القياس).

## الخطوات
١. **السيناريوهان يقولان المحرّك:** خطوةٌ في كلٍّ: `workerPing().psd` رقم المحرّك قبل الاستيراد، ولا سطر `[native]` في سجلّ أخطاء الملفّ الشخصي بعده.
٢. **على البناء:** `npm run build` ثم `designPsd` و`designPsdStyles` و`workerPath` بلا ✗.
٣. **على المحزوم:** `npm run pack` ثم الثلاثة بـ`DIWAN_EXE` على برنامج `release/test/win-unpacked/` بلا ✗.
٤. **القياس** (`tools/experiments/psdSpeed.mjs`، بلا ✓ ولا ✗): ملفّ PSD كبير يُبنى بـ`psdBuilder` (نحو ٤٠٠٠×٣٠٠٠ بـRLE) — وسيط خمس قراءاتٍ لـ`readPsd` بالمحرّك و`readPsdScript`،
   والأرقام في القيد وفي QUALITY §٨ مع الجهاز الذي قيست عليه.
